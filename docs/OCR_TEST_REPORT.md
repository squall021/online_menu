# PaddleOCR 瀏覽器測試報告

測試日期 2026-11-23。Windows 10 x64（19045）、Intel Core i5-13400、Node.js 26.13.0、npm 11.20.0、Vite 7.3.8。使用 Playwright 驅動本機 Chrome 157.0.8103.79 及 Edge 158.0.4370.33。PaddleOCR.js 0.4.2 與 ONNX Runtime Web 1.31.1 使用 PP-OCRv5 mobile det／rec、中文模型、單執行緒 WASM，偵測參數為 `textDetLimitSideLen: 1600`、`textDetLimitType: 'max'`。

### 原始失敗與修正

1. 第一次執行時，受限瀏覽器對 Paddle 模型網域回報 `net::ERR_NETWORK_ACCESS_DENIED`。開放網路後，兩個模型都回應 HTTP 200，並帶有允許當前本機來源的 CORS 標頭。SDK 的 `create` 和模型封存檔可用。
2. 開放網路後，兩張仍在推論前失敗（P1）。ONNX Runtime 對 `node_modules/.vite/deps/ort-wasm-simd-threaded.jsep.wasm` 的請求收到 338 bytes 的 HTML，導致 MIME 錯誤及 WASM magic word 不符。改用 Vite 資產 URL 指向與 SDK 共用的 ORT 版本。預覽版實測回應 `application/wasm`，29,520,971 bytes。
3. 修正後兩個模型合計下載 21,544,960 bytes，偵測和辨識皆走 WASM。Chrome 完成兩次辨識，無失敗網路請求或未捕捉頁面例外。ORT 在主控台輸出移除未使用模型初始值的警告，SDK 初始化摘要也記錄了尚未支援文件前處理和文字方向設定。

## 兩張原圖的量化結果

數據取自 Chrome 的子路徑建置版。同一頁先跑先喝道，接著在已初始化的情況下跑 50嵐。第一次初始化約 5.34 秒。推論時間採 SDK 的 `totalMs`，包含該次偵測及辨識。

|---|---:|---:|
| 原圖尺寸 | 1536 × 1095 | 1536 × 1032 |

| 推論／按鈕至結果 | 10.81 秒／16.62 秒 | 15.66 秒／15.70 秒 |

| 有對應候選的商品 | 49／49 | 54／54 |

## 重現與後續

1. 依 [README](../README.md) 安裝、啟動或建置。在上傳辨識頁逐張選擇先喝道、50嵐，按「開始 PaddleOCR 辨識」並下載原始 JSON。
2. 按「重新解析成商品」，下載菜單 JSON。使用 `ocrItemIndexes` 對照原始檔的 `lines[].index`，再和人工 TSV 的商品列、價格及分類比對。核對待確認標記與能否進入點餐。測試用 TSV 未納入執行程式。
3. 下一階段先切分商品欄、分類及加料／說明區，再針對各欄追蹤 M／L 標頭和價格 X 座標。在尺寸或價格缺失時交給校對。為原圖建立框與候選列的對照，支援逐杯紀錄尺寸、甜度、冰量、加料及價格快照。

**發布判定**　可在已測環境繼續 V1 本機驗證。正式多人團購仍需共享後端及部署環境測試。
